## CaptainDevSubmit

Assessment planning repository for NOVA, a fictional SaaS product. All implementation source lives in a separate candidate-controlled private GitHub repository — no code is written or run here. Planning docs are in `docs/`; normative reading order and source-precedence rules are in `README.md`.

## Policy

- Never modify files under `docs/` — assessment documents provided by CaptainDev, not authored in this repository.

## Where things are

- Reading order and source precedence: `README.md`
- Assessment scope and deliverables: `ASSESSMENT.md`
- Product requirements: `docs/product/PRODUCT-REQUIREMENTS.md`
- Assessment traceability (exact requirements + minimum verification): `docs/product/ASSESSMENT-TRACEABILITY.md`
- Required implementation architecture: `docs/architecture/ARCHITECTURE.md`
- Blocking security invariants: `docs/architecture/SECURITY-INVARIANTS.md`
- UX references and interpretation rules: `docs/ux/README.md`

## Known pitfalls

- `docs/` files are CaptainDev-authored assessment material; proposing edits to them is always wrong.
